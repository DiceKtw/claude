# Windows 重建計畫書 — 剪映國內版閉環驗證

> 基準環境：**Windows + 剪映（國內版，JianyingPro）**
> 本階段目標：**先打通「AI 決策（EDL）→ 剪映草稿 → 剪映可開啟 → 人工可修改」的最小閉環**，
> 不開發完整 AI 功能。
> 本文件只做規劃與驗證流程，不含功能開發。

---

## 0. 閉環範圍定義

```
EDL（已存在的中間格式）
   → 剪映 Exporter（pyJianYingDraft）
   → 剪映草稿資料夾
   → 剪映開啟
   → 人工微調
```

本階段**刻意排除**：STT、AI 評分、字幕軌、模板。
只驗證「一段 EDL 能不能正確變成一個剪映能開的草稿」。

---

## 1. 剪映國內版草稿資料夾確認方式

剪映每個草稿 = 草稿根目錄下的一個子資料夾，內含 `draft_content.json`（或新版 `draft_info.json`）、
`draft_meta_info.json` 等檔案。pyJianYingDraft 需要知道這個「草稿根目錄」。

### 1.1 預設路徑（Windows 剪映國內版）
```
C:\Users\<你的使用者名稱>\AppData\Local\JianyingPro\User Data\Projects\com.lveditor.draft
```

### 1.2 確認步驟（務必實測，不要假設）
1. 開啟剪映 → 進入「全局設置 / 設置」→ 找「草稿位置 / 草稿存儲位置」，記下實際路徑
   （**很多人會把草稿改到 D 槽等其他磁碟**，預設路徑不一定準）。
2. 在剪映**手動新建一個草稿**、隨便拉一段影片、存檔。
3. 到上一步記下的路徑，確認**出現一個新子資料夾**，且裡面有 `draft_content.json` /
   `draft_meta_info.json`。
4. 記錄下這個「草稿根目錄」的絕對路徑 → 之後 Exporter 的 `Draft_folder` 就指向它。

### 1.3 驗收
- [ ] 能明確指出草稿根目錄絕對路徑
- [ ] 手動草稿的子資料夾與 JSON 檔案確實出現在該路徑

## 2. pyJianYingDraft 與剪映國內版相容性驗證流程

> **這是整個計畫的最高風險點。** 剪映國內版多次改版，較新版本可能**改動草稿結構或加密
> `draft_content`**，導致 pyJianYingDraft 產出的草稿**開不起來、或被要求「升級草稿」**。
> 必須在寫任何 Exporter 邏輯前先驗證。

### 2.1 前置
1. 記錄目前剪映版本號（剪映 → 關於 / 幫助）。
2. `pip install pyJianYingDraft`（連同相依一起，之後鎖版本）。

### 2.2 相容性驗證（雙向測試，擇一或都做）
**A. 讀取測試（模板模式）**
- 用 pyJianYingDraft 讀取「1.2 步驟」手動建立的那個真實草稿。
- 能成功解析 → 格式相容。
- 解析失敗 / 亂碼 / 解密錯誤 → **版本不相容**，走 2.3。

**B. 寫出測試（最小草稿）**
- 用 pyJianYingDraft 產一個「空的或只有一段素材」的最小草稿，放進草稿根目錄。
- 開剪映：
  - 能正常開啟、無「升級草稿」提示 → 相容。
  - 打不開 / 要求升級 / 閃退 → **版本不相容**，走 2.3。

### 2.3 若不相容的處置
- 安裝一個 **pyJianYingDraft 官方文件標示為可用的剪映版本**（通常為較舊、未加密草稿的版本）。
- 安裝後**關閉剪映自動更新**，避免被升級回不相容版本。
- 固定：剪映版本號 + pyJianYingDraft 版本號，一起寫進 `requirements` 與本文件的「環境鎖定」表。

### 2.4 驗收
- [ ] 明確得知目前剪映版本 pyJianYingDraft 是否相容
- [ ] 已鎖定一組「剪映版本 × pyJianYingDraft 版本」可用組合

## 3. 從 EDL 產生剪映草稿的最小測試方案

### 3.1 最小範圍（本階段只做這些）
- **1 條影片軌**
- **同一支來源影片**中挑 **2–3 個片段**
- 依 EDL 的排列順序放上時間軸
- **不含**字幕軌、模板、音樂、轉場

### 3.2 時間單位轉換（最容易出錯，需獨立驗證）
- 剪映內部時間單位為 **微秒（μs）**。
- EDL 若以「秒」為單位：`微秒 = 秒 × 1_000_000`。
- 每個片段需分清楚兩組時間：
  - **來源時間範圍（source / trim）**：從毛片的哪一段裁切。
  - **時間軸時間範圍（target）**：擺在成片時間軸的哪個位置。
- **建議先做一個純算式的單元測試**：給定 EDL 秒數 → 驗證換算出的微秒值正確，
  再進到實際產草稿。單位錯會導致片段長度／位置全錯，卻不會報錯。

### 3.3 素材路徑
- 草稿內素材一律使用**該 Windows 機器上的絕對路徑**（例如 `D:\footage\test.mp4`）。
- EDL 的素材路徑欄位必須能承載 Windows 絕對路徑；若 EDL 來自其他平台，需在
  Exporter 這層做路徑轉換（不改 AI 核心）。

### 3.4 產草稿流程（概念，不含實作）
1. 準備一支短測試影片（建議 30–60 秒）。
2. 手工寫一份「假 EDL」：指定該影片 + 2–3 個 `keep=True` 片段的來源時間與順序。
3. Exporter：建立草稿 → 加影片軌 → 依 EDL 建立各片段（來源範圍 + 時間軸範圍）→
   輸出到草稿根目錄。
4. 關閉剪映後再開啟，載入該草稿。

### 3.5 驗收
- [ ] 有一支測試影片
- [ ] 有一份可重複使用的假 EDL
- [ ] 時間單位換算已通過獨立測試

## 4. 第一次成功標準（閉環驗收清單）

| # | 標準 | 通過條件 |
|---|------|---------|
| 1 | 輸入一支測試影片 | Exporter 能讀到並在草稿中正確引用（絕對路徑，非離線紅片段） |
| 2 | 產生剪映草稿 | 草稿根目錄出現新子資料夾，含 `draft_content.json` 等檔案 |
| 3 | 剪映可以開啟 | 剪映正常載入、**無升級/報錯/閃退** |
| 4 | 時間軸片段正確 | 片段**數量、順序、各自長度、裁切範圍**與假 EDL 一致 |
| 5 | 可以人工修改 | 能在剪映拖動片段、加字幕、調整——確認草稿是「可編輯」而非唯讀 |

**全部打勾 = 閉環成立**，才進入下一階段（字幕軌 / 模板 / 接回 AI 決策）。

## 6. 執行順序建議

1. 確認草稿根目錄（第 1 節）
2. 驗證 pyJianYingDraft 相容性（第 2 節）— **不過就先解決版本，別往下做**
3. 準備測試影片 + 假 EDL（第 3 節）
4. 通過時間單位換算測試（3.2）
5. 產草稿並依第 4 節逐項驗收
6. 全綠 → 進下一階段

## 7. 風險登記

| 風險 | 影響 | 對策 |
|------|------|------|
| 剪映新版加密/改格式 | 草稿開不了 | 第 2 節優先驗證；不相容就鎖舊版並關自動更新 |
| 時間單位換算錯（秒/微秒） | 片段長度、位置全錯且不報錯 | 3.2 獨立單元測試先過 |
| 素材路徑為非 Windows 路徑 | 草稿內素材離線（紅片段） | Exporter 層轉成 Windows 絕對路徑 |
| 草稿目錄被使用者改到別的磁碟 | Exporter 寫錯位置、剪映看不到 | 第 1 節以剪映設定實測為準 |
| 中文檔名/字幕編碼 | 讀寫 JSON 出錯 | 一律明示 UTF-8 |
