# 專案交接說明（給本機 Claude Code）

> 這份文件是給「在使用者 Windows 本機執行的 Claude Code」看的交接說明。
> 雲端那個 session 碰不到這台電腦，所以**實機操作由你（本機）執行**。
> 全程使用繁體中文。

---

## 1. 你接手的是什麼

「AI 自動剪輯助手」專案。核心是一條**單向決策管線**：

```
毛片 → AI 理解內容 → 語音轉文字 → 找精彩片段 → 剪輯決策(EDL) → 剪映草稿 → 使用者在剪映微調 → 發布
```

**原則**：AI 只做「剪輯決策」，不直接輸出成片；產物是可讓剪映繼續編輯的草稿；使用者保留剪映內修改能力。

| 測試影片 | `C:\Users\USER\Desktop\IMG_1049.MOV` |
| pyJianYingDraft | 0.3.0（PyPI 最新） |

## 3. 目前進度（repo 現有內容）

| 檔案 | 說明 |

| `docs/windows_rebuild_plan.md` | Windows 重建計畫書 |

**已驗證（雲端在 Linux 上用假影片、真 pyJianYingDraft 0.3.0 跑過）**：
- 腳本能端到端**產生結構正確的草稿**：1 影片軌、1 片段、素材路徑寫入、時間正確。
- 正確 API 是 `append_track(TrackSpec(TrackType.video))`（不是 add_track）。
- 產出的 `draft_content.json` 是**明文**。

**尚未驗證（只能在這台 Windows + 剪映 10.9.0 做）**：
- 剪映 10.9.0 能不能**開啟這個明文草稿**。

## 4. 你現在要做的第一件事：關卡 1 真實驗證

1. **關閉剪映**（否則草稿列表不會刷新）。
2. 安裝套件：`py -3.10 -m pip install pyJianYingDraft`
3. 執行：`spike\run_spike.bat "C:\Users\USER\Desktop\IMG_1049.MOV"`
4. 開啟剪映，逐項確認：
   - 草稿列表是否出現 `spike_test`？能否載入？有無「升級草稿／報錯」？
   - 影片是否正常顯示（**非離線紅片段**）？
   - 能否拖動 / 裁切 / 加字幕（確認可人工修改）？

## 5. 路線判定（本步的核心產出）

- **能直接開 → 路線 A 成立**（明文可行）→ 下一步做「EDL → 草稿的最小映射」。
- **打不開 / 要求升級 / 亂碼 → 路線 B**：用 [jy-draftc](https://github.com/wenshui330/jy-draftc) 對草稿做 `jianying_draft_encrypt_v2` **回加密**（該工具已驗證涵蓋 10.9.0），再放回草稿目錄重開。

## 6. 開發原則（延續）

1. 繁體中文，不用簡體。
2. 模組化；AI 分析與輸出格式分離。
3. 不要一次做完所有功能；每完成一模組先測。
4. Exporter 獨立存在，**不修改 AI 核心**。
5. 保持未來可擴充（字幕軌、模板預留）。

## 7. 注意事項（易踩雷）

- 剪映 10.9.0 草稿**加密**，**不要假設是舊版明文格式**。
- 素材一律用 **Windows 絕對路徑**，否則變離線紅片段。
- 剪映內部時間單位為**微秒**（`"5s"` = `5_000_000`）。
- 寫草稿前**先關閉剪映**。
- 執行 Python 用 `py -3.10`，不要用 `python`。
